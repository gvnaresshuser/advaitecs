Notice something interesting:

SDK = OpenAI SDK

but

API key = Gemini API key

and

API = Gemini API

and

Model = Gemini model
----------------------------------------
The API key belongs to the API/service being accessed, not necessarily to the SDK being used.
----------------------------------------
SDK
  ↓
Which programming library am I using?

API
  ↓
Which service am I communicating with?

API Key
  ↓
Which service am I authenticated to use?

Model
  ↓
Which AI model am I asking to generate the response?
----------------------------------------
The API key should normally be stored in the backend environment, not in your React frontend:

GEMINI_API_KEY=xxxxx
OPENAI_API_KEY=xxxxx
NVIDIA_API_KEY=xxxxx

   ↓
Your Node/Express API
   ↓
SDK + appropriate API key
   ↓
LLM Provider

This is the architecture I would use for your TypeScript training project because it lets you demonstrate Gemini API + Google GenAI SDK, Gemini API + OpenAI SDK, and later OpenAI/NVIDIA APIs without exposing students' keys in browser code.


The Application → SDK → API → API Key → Provider → Model distinction is the key foundation for this entire AI/LLM module.

Think of these as two independent questions:

Question 1: How do I authenticate?

NVIDIA API
     ↑
NVIDIA API Key

Question 2: How do I communicate with it?

SDK / Client
     ↓
NVIDIA API			


| SDK                      | API        | Key        | Expected                  |
| ------------------------ | ---------- | ---------- | ------------------------- |
| Google GenAI SDK         | Gemini API | Gemini key | ✅ Native                  |
| OpenAI SDK               | Gemini API | Gemini key | ✅ Official compatibility  |
| OpenAI SDK               | OpenAI API | OpenAI key | ✅ Native                  |
| OpenAI-compatible client | NVIDIA API | NVIDIA key | ✅ If endpoint supports it |
| Google GenAI SDK         | NVIDIA API | NVIDIA key | 🔎 Verify compatibility   |

Don't teach students that an SDK belongs exclusively to one LLM provider. Teach them how SDKs communicate with API interfaces, and show where cross-provider compatibility is possible.


That last distinction is important because "SDK can connect to another provider" means the provider must expose an API compatible with what that SDK expects. Google's own documentation describes the OpenAI compatibility layer as useful but notes that it doesn't map every Gemini capability 1:1.

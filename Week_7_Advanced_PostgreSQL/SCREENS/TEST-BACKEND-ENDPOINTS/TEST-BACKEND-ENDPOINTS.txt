# 5. Test INNER JOIN ⭐

This is one of the important Week 7 demonstrations.

```text
GET http://localhost:5000/api/employees/with-departments
```

This executes:

```sql
SELECT
  e.employee_id,
  e.employee_name,
  e.email,
  e.salary,
  d.department_name
FROM employees_advaitecs_advpgsql e
INNER JOIN departments_advaitecs_advpgsql d
  ON e.department_id = d.department_id
ORDER BY e.employee_id;
```

Expected type of result:

```json
[
  {
    "employee_id": 1,
    "employee_name": "Ravi",
    "email": "ravi@example.com",
    "salary": "75000.00",
    "department_name": "Development"
  },
  {
    "employee_id": 2,
    "employee_name": "Priya",
    "email": "priya@example.com",
    "salary": "85000.00",
    "department_name": "Development"
  }
]
```

This is our first **SQL → Repository → Controller → Route → HTTP API** demonstration.

One Very Important PostgreSQL Concept
For pagination, we should normally use:
ORDER BY employee_id

before:
LIMIT
OFFSET

For example:
SELECT *
FROM employees_advaitecs_advpgsql
ORDER BY employee_id
LIMIT 3
OFFSET 3;

This gives us stable and predictable pagination.
Without ORDER BY, PostgreSQL does not guarantee a particular row order.
